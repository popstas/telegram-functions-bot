# Telegraf → grammY Migration Plan (merged from 5 codebase audits + grammY docs research)

Target: `grammy@^1.44.0` (Bot API 10.1, `@grammyjs/types@3.28`), plus `@grammyjs/runner` (required, see Risk 1) and optionally `@grammyjs/auto-retry`. Node 24 and `"type":"module"` are compatible. grammY uses node-fetch@2 internally, so `http.Agent`-based proxying works.

## 2. Ranked risk list

1. **Concurrency regression (highest).** Telegraf polls concurrently; grammY's `bot.start()` is strictly sequential. This bot runs multi-second LLM/tool chains — a 1:1 port serializes every chat behind one slow completion. **Must** adopt `@grammyjs/runner` (`run(bot)`), ideally with `sequentialize(ctx => chat key)`; changes launch/stop lifecycle (`RunnerHandle.stop()`), ready-promise wiring, and the multi-bot loop + `scheduleRestart()` retry in index.ts:69-84,157-217.
2. **Dynamic handler registration hard-breaks.** After `start()`, grammY replaces `bot.use` with a throwing function; `on`/`callbackQuery` funnel through it. `confirm.ts:52-64` (per-confirmation `confirm_<ts>`/`cancel_<ts>`) and `commands.ts:140,233` (per-/add_tool click) **throw at runtime**. Requires redesign to static regex handlers + pending Map — the only genuine architectural change, and it must be registered on *every* bot in the multi-bot registry. (Silver lining: fixes an existing Telegraf handler/memory leak; also note two confirmations in the same ms share a `Date.now()` id, and neither add_tool handler answers its callback query — decide parity explicitly.)
3. **Error-shape changes are silent.** `err.response.error_code/parameters.retry_after` → top-level on `GrammyError`. Affects: all four streaming 429 retry loops (stop retrying silently — and existing test fixtures mock the *old* shape, so tests keep passing), send.ts 403 blocked-user branch (falls into failsafe resend → unhandled rejection), the 401 invalid-token launch probe, vision's `err.message` string sniffing. Centralize into one error helper; consider `@grammyjs/auto-retry` to delete the loops.
4. **Synthetic-context machinery.** Three interlocking hacks depend on Telegraf Context internals: `createNewContext` descriptor cloning (5 features funnel through it: audio→text, photo/OCR→text, document→text, reaction→text, business→text), the HTTP `{...lastCtx}` spread (grammY getters copy as nothing → `ctx.message` undefined), and the `{} as Context` lastCtx sentinel (`ctx.api`/`ctx.me` undefined → crash if HTTP fires before first Telegram message; also cross-bot mismatch risk). Correct port: `new Context(update, api, me)` everywhere + flavor props re-attached.
5. **Keyboard wrapper-shape silent breakage.** Telegraf `Markup.*` = `{ reply_markup }` wrapper, spread into extra bags; grammY `Keyboard`/`InlineKeyboard` **are** the reply_markup value. Any missed site (formFlow.ts:72,142,248; onTextMessage.ts:462,523-524,613) sends messages with no keyboard, no error — `Record<string,unknown>` typing masks it. Safest: convert to raw `{ reply_markup: {...} }` literals (pattern already used elsewhere in the codebase).
6. **`persistentChatAction` has no equivalent** and is part of the synthetic-context contract (stubbed in 3 places). Needs a custom interval helper with identical `(action, callback)` shape, supporting `business_connection_id`; 13 test files' ctx fakes + one call-shape assertion change in lockstep.
7. **`ctx.botInfo` → `ctx.me` fails silently.** Multi-bot chat-config routing keys on `botInfo.username` (send.ts:79,225; context.ts:57); a missed read → chatConfig `{}` → messages sent via wrong bot / unauthorized. `bot.botInfo =` assignment is illegal (throwing getter) — `useBot()` must `await bot.init()` or pass `{ botInfo }`.
8. **`editMessageText` signatures.** Positional inline slot removed (streaming.ts:50, send.ts:249 — text shifts into wrong slot, may still compile) and the inline variant needs `editMessageTextInline` (onInlineQuery.ts:239,248 incl. the catch-block path, + 6 test assertions).
9. **`sendMessageDraft` is non-standard** (not in Bot API 10.1). `api.raw` proxy forwards it, but verify the backend still accepts it, and note transformers (auto-retry) now intercept draft flushes — timing changes. Draft-flusher design intentionally keeps `sentMessages` empty; don't "fix" it.
10. **Type gaps + Bot API version jump.** `Chat.TitleChat` and 5 `Update.*` namespace members don't exist in `@grammyjs/types` (~20 sites); grammY types target Bot API 10.1 vs Telegraf's ~7.x — expect unrelated new typecheck errors (Chat vs ChatFullInfo split, MaybeInaccessibleMessage, `forward_from` is dead — history.ts:27 branch can be removed). Heavy `as unknown as` casting means some mismatches compile and fail only at runtime.
11. **`reply_to_message_id` → `reply_parameters`** — grammY typings reject the old key; handlers and send.ts must move together.
12. **`allowed_updates` snake_case.** If dropped/mistyped during the `launch`→`start`/runner port, `message_reaction`, `business_connection`, `business_message`, `chosen_inline_result` silently stop arriving (excluded from Telegram's default set). No error raised.
13. **Test suite gives zero type-level safety net.** Tests are excluded from typecheck (proven: 15 files import a phantom `Context` from `telegraf/types` and pass). All breakage is runtime and tracks *src* seam changes, not the library: 1 full rewrite (bot.test.ts), ~17 targeted-edit files (`.telegram`→`.api` key in ~14 fakes, callApi/editMessageText/429-shape/launch/startPayload/action/answerCbQuery/getFileLink assertions), ~18 files import-swap only. Mitigation: keep mocking at the src seams (`useBot`, `sendTelegramMessage`), don't clean up the `as unknown as` casts during the port.
14. **Proxy unverified.** `https-proxy-agent` via `baseFetchConfig.agent` should work (node-fetch@2) but is undocumented officially — smoke-test bot startup through the proxy first; if a future grammY moves to native fetch/undici the agent is silently ignored.
15. **Atomic-swap blast radius.** Context/Api types flow through send.ts signatures, `ThreadStateType.msgs` (types.ts:220), and every handler — the port cannot land file-by-file on the src side. Plan one migration branch; pre-refactors (below) shrink it.
16. **Business handlers were typed on a lie.** Removing `as unknown as "message"` gives correctly-typed business contexts — expect new type errors and hidden `ctx.message`-vs-`ctx.businessMessage` assumptions in onBusinessMessage. Also: stale ctx objects stored in `secretaryTimers` Maps stay valid (ctx.api is just a client), but verify.

## 3. Suggested port order

### Phase 0 — Pre-refactors on Telegraf (each lands independently, shrinks the atomic swap)
1. **Kill dynamic `bot.action` registration** (Risk 2) *while still on Telegraf*: static `bot.action(/^(confirm|cancel)_(\d+)$/)`, `/^add_tool_(.+)$/`, `/^add_skill_(.+)$/` registered at init on every bot, dispatching via pending Maps. Fixes the leak today; port later is a rename.
2. **Replace `Markup.*` with raw `{ reply_markup }` literals** (Risk 5) in formFlow.ts and onTextMessage.ts (confirm.ts/commands.ts already do this). Works identically under Telegraf; eliminates the wrapper-shape trap entirely and removes the `Markup.Markup<...>` from send.ts signatures.
3. **Extract error-shape parsing** into one helper module (`getRetryAfter`, `isBlockedByUser(403)`, `isInvalidToken(401)`, description extraction) with Telegraf implementation; port = rewrite one file (Risk 3).
4. **Extract a `persistentChatAction`-shaped helper** (`withChatAction(ctx, action, fn)`) wrapping `ctx.persistentChatAction` today; switch all 6 call sites + 3 stubs to it. Port = reimplement one helper with a sendChatAction interval (Risk 6).
5. **Create `src/telegram/types.ts`** with `TitleChat`, `MessageUpdate`, `CallbackQueryUpdate`, `MessageReactionUpdate`, `ChosenInlineResultUpdate` aliases re-exported from telegraf/types now; point all ~20 cast sites at it. Port = change one file's definitions to indexed-access over grammY's `Update`.
6. **Delete dead code**: history.ts `forward_from` branch; retype the fake-context contract if cheap.

### Phase 1 — Foundations (start of the migration branch)
7. Install `grammy`, `@grammyjs/runner` (+ optionally `@grammyjs/auto-retry`). Define `BotContext` flavor. Swap `src/telegram/types.ts` aliases to `grammy/types`.
8. Mechanical repo-wide `telegraf/types` → `grammy/types` import swap (src + tests; pure find/replace, ~40 files).
9. Port **src/bot.ts**: `Bot<BotContext>`, `client.baseFetchConfig.agent`, `bot.init()` instead of `botInfo =` assignment (useBot may become async or defer init to launch), async signal handlers. **Smoke-test proxy immediately.**
10. Port **src/telegram/context.ts**: `createNewContext` → `new Context(update, api, me)` + flavor re-attach; `botInfo`→`me`; alias-based casts. Port **lastCtx.ts** to store `(api, me)`. This is the keystone — test the five re-dispatch paths (audio/photo/document/reaction/business → text) here.

### Phase 2 — Send/streaming layer (behavioral core)
11. **src/telegram/send.ts**: `telegram`→`api`, editMessageText arg fix, `InputFile`, GrammyError helper, `reply_parameters`, signature retype.
12. **src/helpers/gpt/streaming.ts**: `api` rename, editMessageText arg fix, `api.raw` sendMessageDraft, GrammyError retry (or auto-retry transformer). **src/helpers/vision.ts**: getFile+URL, `err.description` sniffing, withChatAction helper. **src/telegram/confirm.ts**: `callbackQuery`/`answerCallbackQuery` renames (already static from Phase 0).

### Phase 3 — Entry point and lifecycle
13. **src/index.ts**: filter queries, native business/reaction handlers, `callbackQuery`, `answerCallbackQuery`, `bot.command("help")`, `bot.catch(BotError)`, `run(bot)` + `allowed_updates` + onStart/ready re-plumbing, 401 via GrammyError, runner-based stopAllBots; rebuild telegramPostHandler on `new Context(...)` + flavor (`expressRes`, `me`).
